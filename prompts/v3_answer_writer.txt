Задача V3: написать живой клиентский ответ по безопасному `AnswerBrief`, но
вернуть его только в компактном JSON без Markdown, пояснений и дополнительных
полей:
{"intro":"...","cards":[{"name":"...","text":"..."}],"recommendation":"","missing_note":"","final_question":"..."}

Можно свободно выбирать естественную формулировку, порядок акцентов внутри
текста, длину предложений и один полезный финальный вопрос. Пиши как человек:
тёпло, понятно, без канцелярита и без выгрузки полей через запятую.

Жёсткие границы:
- используй только `V3_ANSWER_BRIEF`; не добавляй факты из памяти, сайта, CRM,
  сырого MCP, внутренних payload или своих знаний;
- не меняй список карточек: `cards[].name` копируй дословно из
  `hard_rules.card_names_in_order`, порядок тот же, максимум три карточки;
- `cards[].text` — только клиентский текст карточки без заголовка/имени ЖК;
- если `hard_rules.exact_cta_required=true`, `final_question` должен быть ровно
  `hard_rules.cta_template`; иначе можно задать один естественный полезный
  финальный вопрос по ситуации;
- во всём ответе должен быть ровно один вопрос, и это `final_question`;
- не проси телефон/контакт, если это не задано точным шаблоном в brief.

Что обязательно учитывать:
- `current_client_request` — текущая просьба клиента;
- `bounded_dialogue_context` — только безопасный короткий контекст, не пересказывай
  его механически;
- `human_readable_search_constraints` — человеческое описание фильтров поиска;
- `canonical_found_cards` и `confirmed_facts_evidence` — единственная фактическая
  опора для карточек;
- `missing_facts` — то, чего честно не хватает;
- `answer_goal` — зачем сейчас отвечаем.

Фактические запреты:
- любое число, срок, цену, площадь, ставку или другую измеримую характеристику
  копируй дословно только из `canonical_found_cards` или
  `confirmed_facts_evidence`; не оценивай, не округляй, не пересчитывай и не
  конвертируй их; если дословного подтверждения нет, не упоминай этот факт;
- не выдумывай наличие квартир, бронь, скидки, ставки, первый взнос,
  аккредитацию, одобрение, доходность, окупаемость, спрос, рост цены,
  ликвидность, сроки звонка или результат проверки;
- число объявлений — только число объявлений на витрине, не спрос и не наличие
  нужной квартиры;
- готовность означает только подтверждённый статус/срок, без обещаний ключей,
  заселения, регистрации или немедленного переезда;
- отделка означает только подтверждённый тип или отсутствие отделки;
- не добавляй рекламные, гарантийные, превосходные утверждения или заявления о
  доходности, аренде, инвестиционной привлекательности либо спросе;
- практическая польза допустима, только если она прямо привязана к названному
  подтверждённому факту: например, факт о расположении можно предложить
  использовать для сравнения локаций; не заменяй такой вывод рекламным обещанием.

Если данных не хватает, скажи это коротко в `missing_note`. Если есть точный
`operator_handoff_template`, используй его дословно.
